タクシー営業ノート 仕様書

本書は、タクシー営業ノートの現行仕様を日本語で整理したものです。実装時の判断、TestFlight説明、App Store Connect入力、ユーザー向け説明文の土台として使います。

1. アプリの目的

タクシー営業ノートは、個人のタクシードライバーが自分の営業結果を振り返り、給与の実質歩率と乗車傾向を確認するためのiPhoneアプリです。

会社の給与明細、税務書類、配車システム、会社公式レポートを置き換えるものではありません。あくまで本人が手元で営業データを見える化し、次の営業判断に役立てるための補助ツールです。

対象ユーザー

自分の売上、給与、乗車傾向を把握したい個人タクシードライバー。

初期対象端末

Version 1はiPhoneを優先します。iPadやWeb管理画面は初期対象外です。

公開名

アプリ名は タクシー営業ノート、Bundle IDは com.uklab.taxinote です。

2. Version 1 の主要機能

  • 日別売上の入力と保存
  • 締日にもとづく月間売上の集計
  • 給与額から実質歩率を確認する給与チェック
  • CSV日報の取り込み
  • 乗車記録の手動補正
  • 時間帯、曜日、祝日/休前日、乗車区分による乗車分析
  • 主要エリア別の乗車回数と平均運賃の表示
  • MapKitによる主要エリアの地図表示
  • 設定/ヘルプ画面とアプリ内プライバシーポリシー
  • 合成サンプルデータの明示表示と削除

初期版はローカル優先です。保存した営業データをアプリ独自のサーバーへ送信する設計ではありません。

3. 給与チェック仕様

給与チェックは、会社ごとの複雑な給与式を再現する機能ではありません。実際に支払われた給与額を、税抜月間売上と比較して、実質的な歩率を見える化する機能です。

入力項目

項目 内容
日別売上 税抜を標準入力とし、必要に応じて税込入力も選択できます。
締日 標準は15日締め。31を指定すると月末締めとして扱います。
税率 標準は10%。税込入力を税抜換算するために使います。
月間税抜売上 日別売上から自動計算します。会社固有の調整がある場合は手入力で上書きできます。
給与額 総支給、手取り、賞与込み、賞与抜きの4種類を任意で入力できます。
基準歩率 標準は60%。ユーザーが変更した値は次回以降も使います。
メモ 控除、手数料、賞与、特殊な調整などを記録できます。

計算内容

  • 実質歩率 = 入力した給与額 ÷ 月間税抜売上
  • 基準給与 = 月間税抜売上 × 基準歩率
  • 基準との差額 = 入力した給与額 - 基準給与
  • 賞与額 = 賞与込み給与 - 賞与抜き給与
  • 曜日別の平均税抜売上

給与額はすべて任意入力です。入力された項目だけを計算し、未入力の項目は無理に評価しません。

4. 日報取り込み仕様

日報形式は会社やシステムによって変わるため、アプリ本体は特定の見た目や表位置に依存しません。取り込み処理は、最終的に安定した「乗車記録」へ変換する方針です。

取り込み方針

  1. CSV、画像、PDF、Excel、手入力などの入力元を読む。
  2. 日付、曜日、乗車時刻、乗車エリア、運賃、乗車区分を候補として検出する。
  3. 検出結果をアプリ共通の乗車記録に変換する。
  4. 信頼度が低い項目や不足項目は手動補正へ回す。
  5. 確認済みの記録だけを分析や地図表示に使う。

Version 1で扱う主な項目

項目 内容
日報日付 営業日として扱う日付。
曜日 月曜から日曜までの7値。
祝日/休前日 祝日、または需要が変わりやすい休前日として分析に使います。
乗車時刻 22時以降から翌朝5時までは深夜営業日として扱えるよう、内部では25時以降の表現も考慮します。
乗車エリア 日報上のエリア文字列を保持し、主要エリア辞書により分析用エリアへ変換します。
運賃 乗車ごとの金額。エリア別平均運賃の計算に使います。
乗車区分 アプリ配車、流し、無線/配車、不明などに正規化します。

日報に含まれる運転者名、会社識別子、車両番号などは分析用データとして保存・表示しません。個人や会社を直接識別しやすい情報はVersion 1の分析対象外です。

重複取り込み

同じ営業日のCSVを再取り込みした場合、既存件数と手動補正済み件数を表示して、意図しない上書きを防ぎます。現在は明示的に確認した場合のみ、既存日報を置き換える破壊的な置換フローを提供します。

今後の課題として、手動補正を行単位で保持したまま再取り込み内容とマージする非破壊的な更新方式を検討します。

5. 乗車分析仕様

乗車分析は、どの時間帯にどのエリアで乗車が発生しやすいか、またどのエリアの平均運賃が高いかを確認するための機能です。

標準時間帯

表示 内部範囲 意味
5-8時 05:00-08:00 朝の移動開始。
8-12時 08:00-12:00 通勤、業務、昼前の移動。
12-16時 12:00-16:00 昼間の買い物、業務、移動。
16-22時 16:00-22:00 帰宅、夕食、深夜割増前の移動。
22-1時 22:00-25:00 深夜割増開始、終電前後、夜の需要。
1-5時 25:00-29:00 終電後から早朝までの深夜需要。

アプリは現在時刻から標準時間帯を判定し、分析画面と地図画面の初期表示に使います。ユーザーは手動で時間帯を切り替えられます。

フィルター

  • 曜日
  • 祝日
  • 休前日
  • 乗車区分
  • 標準時間帯

表示する指標

  • 乗車回数
  • 合計運賃
  • 平均運賃
  • 主要エリア別の集計
  • 地図上の主要エリアマーカー

6. エリア仕様

初期版では、東京タクシー営業圏を想定した主要エリア辞書を使います。対象は東京23区、武蔵野市、三鷹市を中心とします。

エリアごとの対象区、検索キーワード、利用区分、レビュー注意点は エリア仕様一覧 にまとめています。

エリアの考え方

  • 日報上の元エリア文字列は保持する。
  • 表示・分析用に主要エリアグループへ変換する。
  • 座標は近似値として扱い、将来ユーザー補正できるようにする。
  • 珍しいエリアや未分類エリアは削除せず、other_or_unmapped として保持する。

無料/有料拡張の前提

初期実装では課金機能そのものは作りません。ただし、将来の拡張に備えてエリア辞書はアクセス階層を持ちます。

  • 無料/基本範囲: 20エリア。P1グループと一部P2グループ。
  • 有料/フル範囲: 46エリア。将来的にカスタムエリア編集も検討。
  • エリア番号ではなく accessTier で利用範囲を判定する。

7. データ保存とプライバシー

Version 1はSwiftDataによる端末内保存を前提とします。クラウド同期、アカウント機能、アプリ独自サーバーへの営業データ送信は現時点では実装しません。

端末内に保存する可能性がある情報

  • 日別売上
  • 給与チェック用の入力値と基準歩率
  • 日報から取り込んだ乗車時刻、乗車エリア、運賃、乗車区分
  • 曜日、時間帯、エリア、地図表示のための集計値
  • 手動補正済みかどうかの状態

保存・分析しない情報

  • 運転者名
  • 会社識別子
  • 車両番号
  • 会社公式レポートを再現するためだけの個人識別情報

公開プライバシーポリシーは https://uk-lab.jp/taxinote/privacy-policy/、サポートページは https://uk-lab.jp/taxinote/support/ です。

9. TestFlight準備状態

実装側のTestFlight準備はかなり進んでいます。現在の主な待ちはApple Developer Programの有効化と、その後の署名・App Store Connect設定です。

準備済み

  • アプリ名: タクシー営業ノート
  • Bundle ID候補: com.uklab.taxinote
  • AppIcon設定
  • PrivacyInfo.xcprivacy
  • Privacy Policy URL
  • Support URL
  • TestFlight説明文、What to Test、審査メモの下書き

Apple側で残っている作業

  1. Apple Developer Programの有効化を待つ。
  2. Apple Developerで com.uklab.taxinote をExplicit App IDとして登録する。
  3. XcodeのSigning Teamを設定する。
  4. App Store Connectでアプリを作成する。
  5. 署名付きArchiveを作成してアップロードする。
  6. TestFlightの内部テスターで実機確認する。
